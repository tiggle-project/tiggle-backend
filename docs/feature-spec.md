# Tiggle 기능 명세서

> 최종 갱신: 2026-11-13. 노션 "기능" 페이지의 내용을 옮겨 왔으며, 이제 이 문서가 기능 명세의 원본입니다.

무엇을 만드는지와, 각 기능을 어떤 API가 담당하는지 정리한 문서입니다. 기능이 지켜야 할 규칙(수치, 조건)은 노션 정책서에 있고, 이 문서에는 정책 이름만 표기했습니다.

팀원 모두가 이 명세를 기준으로 각자 구현합니다. 명세를 바꾸면 모든 팀원의 구현에 영향을 주므로, 변경은 PR로 올려 주세요. 누가 확인한 뒤 머지할지는 [협업 규칙](../README.md#협업-규칙)과 함께 팀 논의로 정할 예정입니다.

## 읽는 방법

- **ID:** `도메인-번호` 형식입니다. 문서와 PR 설명에서 기능을 가리킬 때는 이 ID를 사용해 주세요. PR·커밋 제목에 표기할지는 [협업 규칙](../README.md#협업-규칙)에서 정할 예정입니다.
- **사용자:** 구매자(BUYER), 주최자(ORGANIZER), 관리자(ADMIN), 시스템(내부 동작), 개발자(측정·실험 도구) 중 하나입니다.
- **관련 API:** 노션 API 명세서의 엔드포인트입니다. "내부"는 외부에 공개하지 않는 동작입니다. API 명세는 M0에서 공용 `specs/`의 OpenAPI로 옮길 예정입니다.
- **관련 정책:** 노션 정책서에 있는 정책의 이름입니다.
- **마일스톤:** 그 기능을 구현하는 작업 단위입니다. 단계별 작업 단위는 [milestones/](milestones/README.md)에 있습니다.
- Core(M1~M4)는 상세히 작성했고, Plus와 Expand(M5~M12)는 기능 목록만 정리했습니다. 해당 마일스톤을 시작할 때 Core와 같은 형식으로 구체화할 예정입니다.

## 상태 흐름

기능 설명에 나오는 상태 값은 아래 흐름을 따릅니다. 아직 확정되지 않은 초안이며, M0에서 공용 예약 상태 전이도를 만들 때 확정할 예정입니다.

- **좌석:** `AVAILABLE`(예매 가능) → `HELD`(선점됨) → `SOLD`(판매 완료)이고, 선점 만료나 취소 시 `AVAILABLE`로 돌아갑니다.
- **예약:** `PENDING`(선점, 결제 대기) → `CONFIRMED`(확정)이고, `PENDING`에서 `EXPIRED`(만료)나 `CANCELED`(취소)로, `CONFIRMED`에서 `CANCELED`(환불 후 취소)로 갈 수 있습니다.
- **결제:** `READY`(요청됨) → `APPROVED`(승인) 또는 `FAILED`(실패)이고, `APPROVED`에서 `REFUNDED`(환불)로 갈 수 있습니다.
- **회차:** `SCHEDULED`(오픈 대기) → `OPEN`(예매 중) → `CLOSED`(예매 종료)입니다.

## Plus 기능 (M5~M6, 목록만)

- **QUE(M5) 대기열:** 대기열에 들어가기(QUE-01), SSE로 내 순번 받기(QUE-02), 입장 토큰 발급과 검증(QUE-03), 대기열 화면(QUE-04, React)이 있습니다.
- **OPS(M6) 운영 품질:** Idempotency-Key로 중복 요청 막기(OPS-01), 요청 횟수 제한(OPS-02), DB와 Redis 데이터 대사(OPS-03), Toxiproxy 장애 주입 자동화(OPS-04), 알람 규칙과 런북(OPS-05)이 있습니다.

## Expand 기능 (M7~M12, 목록만)

- **NTF(M7) 알림 서비스:** 관심 행사 구독(NTF-01), 예매 오픈 알림(NTF-02), 취소표 알림(NTF-03), 알림 채널 추상화(NTF-04)가 있습니다.
- **SRCH(M8) 검색·랭킹:** 행사 검색(SRCH-01), 예약 통계(SRCH-02), 조회수 집계(SRCH-03), 인기 랭킹(SRCH-04), 재색인(SRCH-05)이 있습니다.
- **CPN(M9) 쿠폰:** 쿠폰 생성(CPN-01), 선착순 발급(CPN-02), 결제 시 적용(CPN-03), 취소 시 반환(CPN-04)이 있습니다.
- **STL(M10) 정산:** 정산 배치 실행(STL-01), 정산 결과 조회(STL-02), 실패 후 재시작(STL-03)이 있습니다.
- **FRD(M11) 부정 방지·감사:** 1인 구매 한도(FRD-01), 봇 의심 패턴 탐지(FRD-02), 변경 이력 기록(FRD-03), 변경 이력 조회(FRD-04)가 있습니다.
- **M12 인프라**는 사용자 기능이 없으므로 이 목록에서 제외했습니다.
