# M4 성능 측정

> [마일스톤 목록](README.md) · 이전: [M3 동시성 2차와 결제](m3.md) · 다음: [Plus 개요](README.md#plus-개요)

- **목표:** 네 가지 동시성 방식을 같은 조건에서 반복 측정하고, 결과를 대시보드와 실험 기록으로 남깁니다. 여기까지가 Core입니다.
- **미리 공부할 기술:** k6, Micrometer와 Prometheus, Grafana 대시보드, 측정 통계(중앙값과 편차). 측정 환경의 GC와 힙 크기는 사전 3회차(JVM과 GC) 내용을 복습합니다.
- **관련 기능:** BENCH-02, BENCH-04, BENCH-05
- **선행 조건:** M3 완료

## 공용 작업

### 1. [공용] k6 부하 시나리오 1~3

- **목표 동작:** `loadtest/`의 k6 스크립트로 1) 핫 좌석 동시 선점, 2) 분산 좌석 선점, 3) 선점부터 결제와 확정까지의 전체 흐름을 누구의 구현에나 같은 조건으로 실행할 수 있습니다.
- **관련 기능:** BENCH-02
- **확인 방법:** 한 팀원의 구현에 세 시나리오를 실행해 결과가 수집되는지 확인합니다.
- **결정 의존:** 시나리오별 가상 사용자 수와 실행 시간(팀 결정)

### 2. [공용] 측정 자동화

- **목표 동작:** `make bench` 한 번으로 데이터 초기화, 워밍업, 3회 반복 측정, 결과 저장까지 수행됩니다.
- **관련 기능:** BENCH-04
- **확인 방법:** `make bench`를 실행해 3회분 결과 파일이 저장되는지 확인합니다.
- **결정 의존:** 공용 작업 1, M2 공용 작업 2(전략 설정 키)

### 3. [공용] 방식 비교 대시보드

- **목표 동작:** `loadtest/`에 Grafana 대시보드 정의가 있어, 누구의 구현이든 같은 화면에서 방식별 처리량, p99 응답 시간, 실패율, DB 쿼리 수를 비교할 수 있습니다.
- **관련 기능:** BENCH-05
- **확인 방법:** 한 팀원의 구현에 시나리오 하나를 실행하는 동안 대시보드에 값이 채워지는지 확인합니다.
- **결정 의존:** 대시보드가 읽는 공통 지표의 이름과 태그(팀 결정). 이 이름은 개인 작업 1에서 각자 노출합니다.

## 개인 작업

### 1. Micrometer 지표 노출

- **목표 동작:** 앱이 Prometheus 형식으로 지표를 노출합니다. 공용 비교 대시보드가 읽는 공통 지표(처리량, 응답 시간, 실패 수, DB 쿼리 수)는 정해진 이름으로 노출하고, 그와 별도로 도메인마다 핵심 지표를 2개 이상 정의합니다(예: 예약 선점 성공·실패 수, 결제 승인 지연).
- **관련 기능:** 없음
- **확인 방법:** `/actuator/prometheus`에 공통 지표와 도메인 지표가 나타나는지 확인하는 테스트. DB 쿼리 수는 Hibernate 통계나 데이터소스 프록시 같은 방법으로 수집할 수 있으며, 방법은 각자 정합니다.
- **결정 의존:** 공용 작업 3(공통 지표 이름)

### 2. Prometheus와 Grafana 구성

- **목표 동작:** Compose에 Prometheus와 Grafana를 추가하면 공용 비교 대시보드가 자기 구현의 지표로 채워지고, 도메인 지표는 각자 만든 대시보드에서 볼 수 있습니다.
- **관련 기능:** BENCH-05(공용 대시보드 사용)
- **확인 방법:** 시나리오 하나를 실행하는 동안 두 대시보드에 값이 채워지는지 확인합니다. 도메인 지표 대시보드의 정의 파일은 자기 폴더에 함께 커밋합니다.
- **결정 의존:** 공용 작업 3

### 3. 네 가지 방식 측정과 실험 기록

- **목표 동작:** 비관적 락, 낙관적 락, Redisson, Lua 네 방식을 공용 시나리오로 3회씩 측정하고, 중앙값과 편차를 [실험 기록 템플릿](../templates/experiment.md)으로 정리합니다.
- **관련 기능:** BENCH-02, BENCH-04
- **확인 방법:** 실험 기록에 측정 환경(CPU, 메모리, JVM이 고른 GC와 힙 크기), 방식별 3회 결과, 중앙값과 편차가 모두 들어 있는지 확인합니다.
- **결정 의존:** 공용 작업 1, 2

## 완료 조건

3회 반복 측정의 중앙값과 편차가 기록되었습니다. Core 완성입니다.
